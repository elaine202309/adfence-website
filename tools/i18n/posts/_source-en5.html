Sometimes the request is fair: a small publisher asking for the advertising that pays for the article. Sometimes the wall is aggressive enough that the page becomes useless, and the site is the one being unreasonable. Either way, you don’t have to switch the blocker off everywhere to get through — and you don’t have to guess which kind of site you are dealing with.

It helps to know how the page knows. Ad-block detection is usually one small test. The page includes an element built to look like an ad — a banner with an ad-like class name, or a script at an address that reads like an ad server — and then checks whether that element appeared. A content blocker hides or refuses exactly those things, so the missing element is the tell. Some sites go further and check the layout, or the gap where an ad should have been.

That is also why the wall feels impersonal: it is. A script checked one element and drew a box when it did not find it. The site has no idea who you are.

The short version: on the General tab, switch on Bypass Anti-Adblock and reload the page. If one particular site still catches on, allow ads for that address only under Site Overrides. The steps for both are below.

Turning on the bypass

  1. Open AdFence and stay on the General tab.
  2. Under Blocking List, switch on Bypass Anti-Adblock.
  3. Return to Safari and reload the page.

The switch counters the common detection patterns and hides the wall they draw. It is a single global setting, so it applies to every site at once; sites that never check for a blocker will not notice any difference.

Like the filter lists, the anti-adblock rules ship with the app and update when it updates. A site that changes its check will be caught up with in the next release — that lag is the update schedule, not a setting you got wrong.

When the wall still appears

Some sites run a check that the shipped rules do not cover yet. There are three narrower options, from least to most permissive.

A site that still catches you

Open Site Settings for that address, and under Site Overrides switch on Whitelist Ads. The site’s ad requests get through, the detection stops finding a blocked element, and every other filter stays on for that site. It affects only that address.

A site that breaks in other ways

If the page misbehaves beyond the wall — a video player that will not start, a form that will not submit — use Pause Blocking for that address. Everything is off there and nothing else changes. The entry stays on the list until you remove it, however long ago it was added.

A wall you can simply hide

When the content is already on the page and only a panel sits over it, the wall is an element like any other. Custom Element Blocker in Site Settings lets you add that one element and hide it; the rules collect on the Custom tab, ready to remove later.

What it can’t get past

  • Content the server never sent. A real paywall withholds the article before it reaches the browser. Nothing in Safari can make the server send it.
  • A check that is newer than the shipped rules. Detection vendors change their tests; the rules catch up with app updates.
  • In-app browsers. Links opened inside Instagram, Facebook, Gmail or Reddit use those apps’ own browsers, where no Safari extension runs at all.

Is getting past it fair?

That is between you and the site. Some ask directly and offer a way to pay or subscribe; others set terms that forbid blocking. The app gives you the switch; the site decides what it serves. If you read a small publication regularly, pausing for that one address is a reasonable trade — the rest of the web stays blocked, and their advertising keeps the page you came for.

If the wall is still there

Check these in order — the first three solve most cases:

  1. The extension is on in Safari. Safari keeps its own switch, and updates can turn it off. The 30-second check is in this post.
  2. The master switch is on. Blocking at the top of the General tab has to be on; while it is off, every extension loads an empty rule list.
  3. Bypass Anti-Adblock is on. If you turned it on for one site and later off again, the wall returns everywhere.
  4. The site is not paused or ad-whitelisted. Both are site settings, and both make the detection succeed on purpose.
  5. Reload properly, or try a private window. A page already loaded keeps the result of the earlier check; a private window starts clean and tells you whether the rule or a saved state is the difference.

If none of that helps, email support@mxcode.com with the address of the page and a screenshot of the wall. That is enough for us to look at the check.

Frequently asked questions

Do I have to switch Bypass Anti-Adblock off for any site?

No. If one site misbehaves with it on, the narrower tools are per-site: allow ads for that address under Site Overrides, or pause blocking for it alone. The global switch can stay on.

Why does the wall come back on a site that used to work?

Detection vendors change their checks, and the rules that counter them ship with AdFence updates. Between the site’s change and the next release, the older rules may no longer match.

Does the site know I bypassed its wall?

It can tell that the wall element is hidden, and some sites redraw it. That is detection of the hiding, not identification of you: no account, name or browsing history is involved.

Is an anti-adblock wall the same as a paywall?

No. A paywall withholds the article on the server until you subscribe, and nothing in Safari can bring back what the server did not send. An anti-adblock wall is drawn in the page after the content has already arrived.

Does turning it on slow pages down?

It adds rules to the same rule list Safari already applies, so there is no extra connection or background process. The effect on page speed is not something you would notice; the switch is there to stop the wall, not to change how the page loads.
